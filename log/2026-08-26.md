## 2. Regbank — from 89% of the design's flip-flops to 35 register bits

Quantified via the per-macro area reports that fell out of Manuel's
placement-region work: `regbank` (`ram` at the time) alone used **4147 of
the design's 4657 register bits** — 30% of the entire device's register
capacity, for a 256×16 memory. `4147 ≈ 256×16 + addr_reg/staged_h`
confirmed the array was really 256 individual flip-flop words, not EBR,
caused by every word getting an explicit `if (!rstb) ram[N] <= <value>;`
in the reset block — a hard EBR primitive has no way to async-reset 256
words to 256 different values in one edge.

**Root cause corrected the standing plan.** The plan (since 2026-08-24)
was to split the regbank into three memories by purpose (config/sampling/
control). Checked the math first: 67 of 256 words carry live, distinct
default values and would need the *same* per-word reset pattern in any
split — splitting alone wouldn't have fixed most of it. The real fix:
move the config/sampling/free region's defaults to an `initial` block
(bitstream-configuration-time only, same idiom `fifo_ram` in this file
already used), dropping active per-word reset for those 191 words so the
array can synthesize as EBR. Pulled `ch_a`/`ch_b`/`stream_enable`/
`data_source_sel` out into small dedicated registers — required, not
optional, since those four are read combinationally every cycle by
`ch_sel` and a hard EBR primitive can't expose a combinational output
for a fixed address.

**Behaviour change, decided with Manuel:** a bare `rstb` pulse no longer
restores the config/sampling table to defaults — only power-on/
reconfiguration does. Checked first whether anything depends on the old
behaviour: nothing today, but Phase B's `doctor`/self-recovery was going
to want *something* like it. Resolved by choosing a better mechanism —
firmware-issued `REG_WRITE`s restoring known-good values, which already
works end-to-end via A.1.1g's existing write path — rather than keeping
the expensive RTL pattern alive for a use case better served differently
anyway.

**Result, confirmed by resynthesis:** `regbank_macro` 4147 → 35 register
bits (99.2% reduction), now backed by 2 real `PDPSC16K` EBR blocks (was
0). Whole design 4657 → 545 register bits (33.7% → 3.9% of the device);
the 256-deep read-address `WIDEFN9` wide-mux LUTs collapsed 2752 → 32.
STA clean. One small, expected residual: `DPR16X4 × 16` (LUT-based
distributed RAM, not registers) — the dead `rhd2164_sampling_cmd0-3`
ports forcing a small side copy of the table since LSE doesn't optimize
across the module boundary those still-connected-but-unused ports sit on;
resolves once A.1.4's already-tracked deletion of those ports lands.

## 5. Parametrization review — four modules with false generality, two real bugs

Reviewed every module in the reorganized tree for whether its use (or
non-use) of `parameter` was a good design choice. Checked macro coupling
and instantiation-site overrides systematically rather than by
inspection alone — found:

- **`ch_sel` (`n`) — real bug.** `data0`/`data1`/`data0_synced`/
  `data1_synced` correctly scale as `[n-1:0]`, but `ch0`/`ch1` (which
  actually drive `dout`) and the dead `cnt0` debug counter were
  hardcoded `[15:0]` regardless of `n`. Silently mismatched `dout`'s
  `[2*n-1:0]` port width for any `n != 16` — masked only because nothing
  had ever instantiated it at anything else. Fixed; removed the dead
  `cnt0` and its orphaned commented-out block (superseded by
  `test_pattern_gen.v`) along the way.
- **`spi_master` / `spi_master_rhd2164x2` (`n`, `m`) — real bug.** The
  shift-register data path scales with `n`, but
  `spi_master_controller_std`/`spi_master_controller` hand-unroll
  exactly 16 SCK states (`sck0b`..`sck15d`, verified: 16 explicit
  `localparam sck*` lines in each, no loop). Changing `n` would resize
  the registers but not the number of clock edges generated — silent
  data corruption, not just a mismatch. `m` was entirely unused in both
  (only in comments referencing itself).
- **`regbank` (`DATA_WIDTH`, `ADDR_WIDTH`) — misleading, not broken.**
  `DATA_WIDTH=16` is pinned by `main_controller.v`'s 3-transfer WRITE
  sequence and `dtx_mux_reg.v`'s fixed 16-bit `ram_din`; `ADDR_WIDTH=8`
  is pinned by `addr_reg`/`staged_h` being hardcoded `[7:0]` to match
  the SPI0 protocol's one-byte-per-transfer address field. Neither
  sibling module has a parameter of its own — the real constraint lives
  outside `regbank.v` entirely, invisible from reading the file alone.

**Fix, agreed with Manuel:** rather than either (a) rewrite the
timing-critical, already-hardware-verified `spi_master_rhd2164x2` FSM to
genuinely scale — risking the cycle-exact behaviour
`fpga-timing-constraints.md`'s csb/rx_a_en/rx_b_en analysis was derived
against, for no present benefit — or (b) leave the false generality
undocumented, converted all four to `localparam` (kept in the `#(...)`
header only because Verilog needs the value declared there before the
port widths that use it), deleted the confirmed-dead `m`, and removed
the four now-illegal `#(...)` overrides at their instantiation sites
(`ch_sel0`/`regbank0` in `kuntur_fpga.v`, `mcu_spi` in `tb/kuntur_tb.sv`)
— every one had been restating the existing default anyway, so this was
a textual no-op everywhere.

**Verified via full resynthesis + STA**, run directly from the CLI this
session (`radiantc`, Radiant's own auto-saved flow-stage Tcl scripts —
synthesize/map/par all completed with 0 errors) and then again by Manuel
after a further resync: area identical to before across every fix
(`regbank0_macro` still 35/13824 register bits, whole-design still
545/13824, `SLICE 9%`/`LUT 5%`/`EBR 42%`) — confirming all four were pure
header changes with zero synthesis impact, as predicted. Final STA: 0
negative-slack endpoints on all three corners (setup 85°C/0°C, hold
m/0°C), `spi1_csb` worst slack 1.539/1.526 ns consistent with prior
runs, constraint coverage 96.4491% (the §1 `spi0`/`rstb` exceptions
confirmed active). Only `spi2_miso0`/`serial_lvds_rx` remain
unconstrained, both expected.

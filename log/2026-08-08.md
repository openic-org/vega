## 2. A.1.1 redefined — a verification ladder, not a one-line fix

The plan framed A.1 as "the FPGA has never sent neural data — `dout` is
overridden with a ramp." True, but connecting it proves nothing on its own:
between the RHD2164 MISO pins and `fifo_din`, a value can be **real but
wrong** (MISO sampling timing, DDR A/B demux, the two-command pipeline
offset, slot→channel alignment), and none of that is observable against a
synthetic ramp.

**Manuel's key contribution:** the chip supplies its own known values, so none
of this needs an electrode or a signal generator. That is a clean boundary
against A.3, which starts where this ends — injected analog signals,
characterisation, µV numbers.

From the datasheets:

| Source | Expected | Proves |
|---|---|---|
| Reg 59 A/B marker | 53 on MISO A, 58 on MISO B | Purpose-built by Intan for SPI integrity and MISO timing. Asymmetric → catches an A/B swap outright |
| Regs 40–44 | `INTAN` in ASCII | Wrong pipeline offset shows as rotated letters |
| Regs 63/62/61 | 4 / 64 / 1 | Chip presence and identity |
| Channel 48 | `VDD = 0.0000748 × result` | First test of the actual ADC. A module only — B result is meaningless per datasheet |

Tasks A.1.1a–f recorded, each with a numeric pass/fail. **A.1.4 (the sampling
placeholder slot) was promoted to "do this first"** — a, b, c and f all need a
way to inject an arbitrary command into the sampling cycle, so it is the
enabler for the ladder rather than the side task the plan had it as.

## 3. A.1.1g — regbank access, four revisions

Started as "widen the address decode." Ended somewhere quite different.

**Revision 1 — the constraint.** Two limits, not one: `regbank_addr0 =
{2'b10, spi0_drx[13:8]}` confines access to words 128–191 (and since `addr0`
feeds both paths, that limits **reads as well as writes** — initially
understated as a write-only problem), and `regbank_din0 = {8'd0,
spi0_drx[7:0]}` makes every write 8-bit. A sampling slot holds a full 16-bit
RHD command word, so 2 + 8 + 16 = 26 bits are needed in a 16-bit transfer.
Indirection is forced, not chosen.

**Revision 2 — the memory map.** Manuel objected to the layout: ports in the
middle, and both RHD tables wasting most of their 64-word regions. Root cause
was `rb_addr1 = {1'b0, rhd_dtx_sel, cnt0}` building its mux out of bit
concatenation, forcing 64-word alignment regardless of use. Replaced with
base+offset (small adder, timing impact accepted). New map: config 0–47
(34 used), sampling 48–95 (33 used), free 96–191, control 192–255. Headroom of
48 justified rather than round — the datasheet recommends three alternate-
command slots where this design has one, plus auxin1–3, VDD and temperature
if ever sampled in-cycle. Map single-sourced in `intan.vh`. Sizes parametric.

**Revision 3 — Manuel's question: why address-sensitive at all?** The scheme
still kept a directly-addressed window as a fast path, which reaches only 64
words and earns nothing once indirection exists. Dropping it made the `addr`
field a pure port selector: one way to reach RAM, identical for all 256 words,
`ch_a`/`ch_b`/`stream_enable` no longer privileged.

**Revision 4 — what Manuel actually built, and why it's better.** He
implemented a positional 3-transfer FSM sequence rather than a port selector.
The argument that settled it: **SPI0 is already positional** — `FIFO_POP` has
always been two transfers, ChA then ChB — so a sequenced write keeps one idiom
across the interface instead of two. The earlier recommendation had weighed
robustness and ignored consistency.

Landed as a hybrid: keep the positional sequence, add the `addr` field back as
a **redundant sequence tag** (1/2/3) checked at every stage. That recovers
what bare positional loses — self-describing logic-analyzer traces, and a
transfer lost on the wire becoming a *detected abort* instead of the FSM
silently absorbing the next unrelated transfer as the missing one. Cost: three
comparators.

**Transfer lengths, settled last.** Review found `NOP` and `REG_READ` were
both built as mandatory 2-transfer pairs. The `NOP` case was a real bug: a
lone `NOP` was consumed by its own wait state and **swallowed the transfer
after it**, making `NOP` unusable for padding, as a carrier to clock out a
pending `REG_READ` value, or as a resync primitive — sending NOPs to recover
would have eaten the commands that followed. `REG_READ` as a pair had no
justification either, unlike `POP` where the pair is real. Both are now single
transfers. Principle recorded: **multi-transfer structure only where something
forces it.** Resulting invariant: every transfer either starts a new command or
is an identified part of a sequence, and none is ever silently consumed.

## 4. Bugs caught in RTL review

Six, in order found. All fixed by Manuel the same session.

1. **Combinational taps not moved with the tables.** `ch_a`, `ch_b`,
   `stream_enable` and `rhd2164_sampling_cmd0-3` still read words 128–133/164
   after the map moved them to 192+. Those words landed in the new free region,
   uninitialised and unreachable by SPI0. `stream_enable` would have read X in
   sim and 0 in hardware — **streaming dead** — and `SET_CHANNELS` would have
   written 196/197 while `ch_a`/`ch_b` read 132/133, so A.2's round-trip would
   have failed as a silent mismatch.
2. **`regbank_port_sel` declared 1 bit** in `main_controller`, 2 bits at the
   top level and in `ram`. `2'd2` truncated to `1'b0` and bit [1] was undriven,
   so the `case` fell to `default` every time and **`staged_h` was never
   written** — every commit would have been `{8'd0, data}`, i.e. still an 8-bit
   write, with the feature appearing inert and no error anywhere.
3. **Spurious `regbank_wen` in the decode state.** The transfer meant only to
   load the address also committed `{stale_staged_h, new_low_byte}` to the
   *previously* addressed word, corrupting it on every address load.
4. **`idle` jumped to `op0a` after the state rename.** `op0a` only exists in
   `rhd2164_controller`, a different module. Would have been a compile error
   under `` `default_nettype none ``; if it slipped through, the FSM would
   ping-pong between `idle` and an undefined state forever — **SPI0 dead after
   every reset** with nothing obviously wrong in the source.
5. **`NOP` swallowing the following transfer** (see §3).
6. **`REG_READ` as a mandatory pair** with no justification (see §3).

**Unexpected win, still unconfirmed.** The FSM rewrite appears to eliminate the
ChA/ChB pairing hazard entirely. The phase used to free-run because
`mcu_dtx_sel`/`mcu_dtx_en` were driven unconditionally on every transfer —
that is the origin of the "register writes must be an even-numbered batch"
rule and the leading suspect for the historical 32-bit FIFO channel-swap bug.
The new FSM drives the phase explicitly per state; only `op_pop0`/`op_pop3`
ever select ChA/ChB. Verified by reading every state, **not yet in
simulation**. If it holds it retires three MCU-side workarounds at once.

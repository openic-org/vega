## Phase stepper: requirements, RTL (Manuel), testbench

- **Requirements agreed (Manuel)**, now in spec §3.2:
  - D1: the stepper starts on a one-`clk` strobe from the regbank when
    word 233 is written (`wen` and address 233), not on a change of the
    stored word. The scan writes N = 1 over and over, and an unchanged
    word gives no edge.
  - D2: SPT comes from `clock_gen` as a constant output, beside the PLL
    it describes.
  - D3: advancing steps (direction 1) are implemented, but the procedure
    never uses them.
  - D4: N ≥ SPT is allowed; `PHASE_POS` wraps.
  - `PHASESEL` stays the constant `001` in `clock_gen`. It selects CLKOS
    and has nothing to do with `mosi_sel` (an early draft had them
    wired together).
- **`PHASE_POS` accumulates across writes, and there is no command to
  clear it on its own.** It is the only record of where CLKOS is,
  because the PLL takes relative steps and keeps them. Back to 0 is
  SPT − `PHASE_POS` delaying steps, which moves the counter and CLKOS
  together.
- **Reset (decided):** `rst_n_clk`, which already follows
  `rstb && pll_lock` asynchronously. No new reset at the top.
  - Correction to the 11-04 spec: "a lock drop puts CLKOS back at its
    static phase" was an assumption, never checked against the TN.
  - An `rstb` reset clears the counter but not the PLL phase, so the two
    disagree until the FPGA is reconfigured. A lock drop may do the same
    (unverified).
  - This is harmless outside a scan: `mosi_sel` = 4 doesn't use `clk_tx`,
    and #6b's setting is a static phase in the bitstream.
  - A scan therefore starts from a power-cycled Kuntur.
  - Optional bench check in the R1a session: step to SPT / 4, drop lock,
    repeat one point.
- **RTL (Manuel):** `phase_stepper` and the `spi1_eye_scan` shell are in
  `kuntur_fpga.v`. The shell is instanced with no connections yet, so
  the design's behaviour is unchanged. Both branches of `clock_gen`'s
  generate are named `g_pll` (S6). Not built in Radiant yet.
- **First review found seven bugs**, each confirmed in a scratch
  simulation:
  1. it never started (IDLE tested the old `n`);
  2. it sent only one pulse (it toggled the default value, not
     `phasestep`);
  3. PULSE never exited, and the 11-bit counter's wrap repeated the
     steps every 2048 `clk`;
  4. busy was 0 while pulsing;
  5. `PHASE_POS` was cleared in IDLE, and had no power-up reset;
  6. the direction was inverted;
  7. widths and implicit 1-bit nets.

  Manuel fixed them in two passes.
- **`tb/phase_stepper_tb.sv`** (new): the stepper drives `pll_sim`, so
  every command also checks the counter against the model's phase.
  - Coverage: N steps = N edges; both directions and both wraps; a full
    turn; N = 1023 and N = 0; pulse widths and the 5 ns `PHASEDIR`
    set-up; busy for 2N `clk`; a write while busy is ignored, one right
    after is taken; no pulses over 2100 idle `clk`; `rst_n` mid-run,
    alone and with a lock drop.
  - **86/86 at 25k and at 28k** on Manuel's fixed stepper. It was also
    checked to fail on the earlier versions.
- **`kuntur_tb`:** the PLL paths now use `g_pll`. Results: 43/52/43
  checks, the same 6 known failures. `eye_models_tb` 15/15.
  `run_kuntur_tb.sh` now also runs the stepper testbench at both rates.
- **`pc-app/mosi_eye_scan.py`:**
  - new `PhaseDesync` error: `PHASE_POS` is checked after every step and
    after each point's counters, and a row is kept only if it is still
    where the scan put it;
  - on a desync, the script doesn't step back. It restores the bypass
    and the sampling table and says to power-cycle;
  - new test: an FPGA reset at four points in a scan. 9/9 tests pass,
    and the new test fails without the per-row check.

## 3. nRF52840 DK bridge firmware

**Toolchain:** nRF Connect SDK v3.3.0 (Zephyr v4.3.99), SoftDevice Controller

### Key design

```
BLE Central (scan "Kuntur-N") → connect → MTU 247 → discover 0xFFF0/0xFFF2
    ↓ bt_gatt_subscribe (notify)
BLE notification callback → K_MSGQ (32 × 244 B)
    ↓ USB TX thread
IRQ-driven TX ring buffer (16 × 248 B) → CDC IRQ → uart_fifo_fill()
    ↓ USB CDC ACM (/dev/ttyACM3)
PC
```

### Issues resolved during session

| Issue | Root cause | Fix |
|---|---|---|
| 20-byte packets | No MTU exchange before discovery | Added `bt_gatt_exchange_mtu()` before `start_discovery()` |
| No data on ttyACM3 | DTR check never set (IRQ callback not wired) | Poll `uart_line_ctrl_get()` every 200 ms in USB TX thread |
| Bridge locked up | `uart_poll_out()` blocks when PC stops reading | Replaced with IRQ-driven ring buffer + `uart_fifo_fill()` |
| `*float*` in logs | picolibc in Zephyr LOG_INF doesn't support `%f` | Integer arithmetic: `interval × 125 / 100` |
| PHY update fails | SDC central role returns `Feature Not Supported` | Removed `bt_conn_le_phy_update()` call; 1M PHY sufficient |
| Kconfig warnings as errors | `CONFIG_BT_BUF_ACL_RX_COUNT` doesn't exist in NCS 3.3 | Removed invalid option; always clean-rebuild after prj.conf changes |

## 1. The bug: the read path never loaded `addr_reg`

Found by Manuel. `addr_reg` is loaded only under `regbank_port_en`
(`components.v`), and the only state asserting it with `regbank_port_sel = 2'd1`
was the **write** branch of `op_decode1`. So `REG_READ` returned
`ram[addr_reg]` holding whatever the last *write sequence* had left there —
**a word could only be read by first writing it.**

This directly contradicted the as-built description in `PLAN.md`, which claimed
a `doctor` self-test "can simply send the address it wants". Plan corrected.

**Fix, two parts:**

1. `op_decode1`'s read branch now asserts `regbank_port_en = 1'b1`. Since that
   state already drives `regbank_port_sel = 2'd1`, the 8-bit address is routed
   from `din0[7:0]` by construction. This matters: the 6-bit `regbank_port_addr`
   field (`spi0_drx[13:8]`) carries the *tag*, and using it as the address would
   have capped reads at word 63 — leaving `ch_a`/`ch_b`/`stream_enable`
   (196/197/228) permanently unreachable.
2. The read branch also requires `port_addr_is_1`, so a read carries tag 1.

**Consequence worth recording: tag 1 now uniformly means "load address"** for
both `REG_READ` and `REG_WRITE` transfer 1. That is a better answer than the
don't-care address field the design had been heading for — one idiom instead of
two, and reads stay self-describing on a logic-analyzer trace. A read with the
wrong tag falls through to `op_nop0` like every other abort.

## 2. Follow-on: a one-clock read was off by one

Raised in review before the fix was committed. `dout0` is registered
(`dout0 <= ram[addr_reg]`) and `dtx_mux_reg` latches on the one-clock
`mcu_dtx_en` pulse, so loading `addr_reg` and presenting the value in adjacent
states returns the **previously** addressed word:

| Edge | `addr_reg` | `dout0` gets | State | `mcu_dtx_en` |
|---|---|---|---|---|
| N | old | — | `op_decode1` | 0 |
| N+1 | **new** | `ram[old]` | `op_read0` | 1 → latches `ram[old]` ✗ |

Fixed by splitting into `op_read0` (settle, no `mcu_dtx_en`) → `op_read1`
(present, `mcu_dtx_en`, `sel = 2'd2`). Still **one SPI transfer on the wire** —
only two FSM clocks, with hundreds of core clocks of slack before the next
transfer, so it costs nothing. Timing re-traced and correct.

The same structure exists on the write path (`op_write5` commits, `op_write6`
presents `dout0`). Harmless, since nothing consumes a write's return value —
but the write cannot echo back the committed word if that is ever wanted.

## 3. `ram`'s `default:` port case

Was `default: addr_reg <= din0[7:0]`; now `default: ;`.

Clarified in discussion: this is a **clocked** block with non-blocking
assignments, so `addr_reg`/`staged_h` are already flip-flops — an unassigned
branch means "hold", which synthesizes to a deasserted clock enable, not an
inferred latch. That concern applies to combinational `always@(*)` blocks only,
and the `2'd1`/`2'd2` branches already rely on the same idiom (when `sel==1`,
`staged_h` holds).

**Holding beats zeroing.** `default` is unreachable today (`port_en` is only
asserted in states that also drive `sel` to 1 or 2), so it exists purely as
protection against a future bug. Under "hold", a stray `port_en` pulse corrupts
nothing; under "zero" it silently resets the address pointer to word 0 and the
staged high byte, turning a stray pulse into a wrong write at a wrong address.

Suggested and not yet applied: a `$error` in that branch inside
`translate_off`/`translate_on`, so an illegal `port_sel` is loud in simulation
and free in hardware — same reasoning as the tag checks, turning a silent
desync into a detected one.

## 4. Testbench ported to the new protocol

`kuntur_tb.v` had been left on the pre-A.1.1g wire format — its writes used the
old direct-address form (`{2'b01, 6'd4, ...}`), which under the new FSM fails
the tag check at `op_decode1` and aborts on transfer 1. Every write in it was
aborting; the reads then returned `ram[addr_reg]` with `addr_reg` never loaded.
A run would have looked broken without the RTL being broken.

Now ported: tagged 3-transfer writes to words 196/197, self-addressing reads of
the same, NOP carriers after each read, and a POP group. Runs clean.

## 5. Review findings → tasks

Recorded in `PLAN.md` as **A.1.1g-tb**, ordered by value. The two that matter:

- **The 16-bit write path is never exercised** — both write sequences stage
  `8'd0` as the high byte, so the commit is indistinguishable from the old 8-bit
  write. This test would still pass with review-bug #2 present (the
  `regbank_port_sel` truncation that left `staged_h` permanently unwritten).
  Widening writes to 16 bits *is* the feature.
- **The pairing claim still isn't tested** — the stimulus is grouped by opcode
  (six POPs, then writes, then reads), and the hazard only appears with register
  traffic *between* POP pairs.

Also: abort paths untested, `spi_xfer` task to collapse 15× repeated stimulus,
dead old-protocol parameters to delete.

## 6. Flagged: sim-only PLL bypass in the working tree

Simulating requires commenting out the `pll0` instance and enabling
`assign clk = clkin` (`kuntur_fpga.v:101`). That edit is currently uncommitted
in the working tree and is one `git add -A` from becoming the bitstream — a
build with it would silently run the whole design at `clkin`. Same class as the
T3.3 debug hijacks, but with a clean elimination available: put both arms behind
`` `ifdef SIM `` and pass `+define+SIM` in the QuestaSim invocation only. Added
to `PLAN.md` next to T3.3.

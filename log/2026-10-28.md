## Error count in `frame_checker`

Requirements listed from §6.6 first (seed the expected `cnt` once, +1 at
each `pos` 7 → 0; all 64 bits; no re-hunt; saturate at `FFFF`; N =
`NB_ERRORS`). New unit test `tb/frame_checker_tb.v` (kuntur): an ideal
aligned stream, reset at each of the 8 byte positions; modes clean,
`+inj=k`, `+flood` (every bit wrong, 64 × N), `+dead` (no lock).

Three rounds:

- `frame_b4`/`frame_b5` undriven (`errors` = X); `errors_en` a latch (no
  default); window ended at `NB_CHECK` (100) instead of `NB_ERRORS`, and
  `frames` wrapping at `NB_ERRORS` meant that with N = 20 < 100 neither
  `done` nor the no-lock timeout ever came; expected `cnt` stepped by a
  free-running counter, not `pos`, and seeded without + 1; saturation
  could wrap (`FFFE` + 8).
- Then: still the `frames` wrap (no-lock never fired at N = 20, `+dead`
  hung); window 8N + 1 bytes (flood gave 1288 for 1280; `+inj` cannot
  see it, the extra byte is a fixed one); output could show the wrapped
  sum for one cycle when crossing `FFFF` on the last byte. Typo
  `frame_is_` / `frames_is_` survived only as an implicit wire.
- Then all six runs PASS (N = 20: clean, `+inj=4`, flood, dead;
  N = 1100 and N = 1024 flood, the latter crossing `FFFF` on the window's
  last byte).

The count window starts at `pos` 1 of the block after the two clean
blocks, the same point every time.

## Sweep controller in `cdr_fsm` / `cdr`

Requirements listed from §6.6 and from what `cdr_tb` checks. Rounds:

1. **Clean if `errors` = 0 alone** made ALIGN failures and checker
   no-locks clean (both leave `errors` at 0): with no data it would have
   reported success. Fixed: clean = aligned, locked, 0 errors.
   `best_len` was a 1-bit port.
2. **`meas_en` one cycle ahead of `meas_*`** at the ports (internal
   capture was right; Manuel asked what "export" meant): the port is now
   a registered copy. **Trackers not cleared in `idle`**: Manuel asked
   whether that is not what `rstb` is for. Answer: `rstb` is the global
   reset (power-up, start-up sequence), but a re-lock failure and a lock
   loss both start a new sweep through `idle` with `rstb` high, so
   per-sweep state belongs to `idle`.
3. **Run tracker**, two rounds. Off-by-one starts, the first run never a
   candidate, the last run never compared (no `meas_en` after 279), the
   join missing step 279, all-clean giving `FAIL` (later 558 wrapping to
   46), the join applied when 279 was bad, and a + 1 bias that let a
   longer run lose. Replaced by a running maximum on clean steps (spec
   §6.6 *As built*). Tested on its own against `cdr_tb`'s rule: 3,000
   sweeps, all match.
4. **Go to the centre.** First version merged the 279 step with the
   first centre pulse, then gave 1-`wclk` pulses and pulsed once more at
   the centre (the count came out right by luck). Restructured:
   `op4a` → `WAIT` (8 high) → `MOVE_TO_CENTER` (check first) →
   `MTC_LOW` (2 low). `phase` and `eye_center` were 1-bit inputs to
   `cdr_fsm`. `rdy`/`valid`/`eye_width` were undriven ports. Port
   renamed `centre` → `eye_center` in the tb and spec (Manuel).
5. **Re-lock.** The first `cdr_tb` run ended at the centre after
   280 + 176 pulses with `bitsel` 7 for 6: the 2-bit shift a full turn
   causes (Manuel asked for the reason again; explained: a turn delays
   ECLK one period = 2 bits while ECLKDIV keeps counting). Re-lock added;
   first without `checker_start` (checker idle, no `done`), then
   `RELOCK_3` looping to `RELOCK_1` (checker reset every 3 cycles). Both
   fixed.
6. **Lock loss**: `lock` in every state through a two-flop synchroniser,
   first clocked by `clk` (12 MHz) while the FSM runs on `wclk`, a
   crossing the simulator cannot see. Moved to `wclk`.

## `cdr_tb` change: `meas_phase` check race

The defaults run (1 step) and `+q7first` (8 steps) reported
`meas_phase` off the PLL. Not the RTL: on the no-lock paths the FSM
starts the step's `PHASESTEP` pulse in the same cycle as its
measurement pulse; the port `meas_en` is one `wclk` later, and when the
12 MHz edge falls just after the register changes, the pin falls about
86 ns later, before the next `wclk` edge (87.8 ns). The tb now compares
against the PLL step as of the previous `wclk` edge (`step_prev`).

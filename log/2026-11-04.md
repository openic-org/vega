## T4 task #4: K7 `tun_aux` (Manuel's RTL, Claude's tb)

`kuntur` `e69999e`. Spec: `docs/interfaces/lvds-tunnel.md` §4.8.

**RTL:** new module `tun_aux` on `clk` / `rst_n_clk`, and an
`announce` output on `capture_buffer` (combinational,
`xfer_done && t == 1 && primed`, the edge `frame_rdy` toggles on).
- Shadow of RAM registers 0–21 from every `WRITE` at `rhd_start`;
  `dirty` on a changed value. `shadow` and `shadow_snap` are in a
  no-reset block (the walk writes all 22 before frame 0).
- At `announce`: `flags_snap`, `shadow_snap`, `send_config`
  (`dirty` or 1000 frames), `send_status` (300 frames, held pending
  behind `CONFIG`), `dirty` cleared.
- **`dirty` resets to 1.** After a lock drop the walk rewrites the
  same values, so without this, frame 0's `CONFIG` would carry
  `CONFIG_DIRTY = 0`, against §4.4.
- `flags_snap` now drives `frame_builder`'s flags byte. Not yet used:
  `send_config`, `send_status`, `cfg_addr`/`cfg_byte`, and the
  capture buffer's `alt_cmd`/`alt_answer`.

**Review findings, fixed by Manuel:** `cfg_byte` undriven; `shadow`
with two drivers; `shadow`/`shadow_snap` without a reset value inside
the async-reset block; `output reg` driven by `assign`; a missing
comma in the instance.

**tb (K8):** `flags` checked against a `CONFIG_DIRTY` reference built
from the `WRITE`s the RHD2164 models execute (not from the DUT). 9g:
`CONFIG_DIRTY` on exactly 3 frames: frame 0 at start-up, frame 0
after 8b's restart, and frame 11, during which T2 put
`WRITE(21, A5)` into sampling entry 0 (the walk wrote `FF`): a live
test of "changed while sampling". Mutation (`dirty` never set by a
write) fails 9b and 9g. 48 checks, 6 failures, all pre-existing
(T5/T7 FIFO pairs, `csb_reg` reset value).

## `clk` → `wclk` cut in STA

`kuntur` `b0760f2`, `impl_1.pdc` (Manuel added it; text drafted by Claude).
`set_false_path -from [get_clocks clk] -to [get_clocks wclk]`.

- **In the `.pdc`, not the `.sdc`.** `wclk` is derived by Radiant from
  `ECLKDIV` (`clk`/4) after synthesis, so a `get_clocks wclk` in the
  `.sdc` is dropped without an error. The companion's `.sdc` already shows
  this: its async group names `kuntur_clk_os wclk`, the `.srp` says
  `No clock matched`, and the group in its `.twr` has neither. **Open
  (companion):** that constraint does not do what its comment says.
- **One direction only.** `wclk` → `clk` stays timed (one path, slack
  63.8 ns): it is not part of the handshake, and `ODDRX4`'s gearing
  between `wclk` and `eclk` (`clk` through `ECLKSYNC`) is synchronous.
- **Build 2026-11-04 (timing only, no new `.bit`):** the constraint
  resolved; `wclk` "From clk" = False path; 0 timing errors (setup at
  85 °C and 0 °C, hold); coverage 99.1% (was 98.4%); `wbank` mapped to 1
  EBR (pseudo dual port); 957 registers, 1179 LUT4s. Tightest path is
  still the RHD side, `csb_reg` → `spi1_csb` 0.943 ns (placeholder board
  delays; 0.915 ns on 08-27). `tun_clk`, `tun_data` unconstrained, as
  expected (bench-checked, R1a).

**#6a decisions (Manuel), on Claude's requirement list:**

   relationship at each chip.
2. The MCU runs the sweep through the regbank.
3. Test traffic from the sampling table (known answers only).
4. `WRITE` echo: explained; register to pick in the spec.
5. In all builds, idle unless commanded.
6. Phase = middle of the window error-free on all four halves, G5 margin
   rule, per rate. **Temperature check after the animal test.**
7. Written before the first run, Manuel's hypothesis: chip0 and chip1
   have different MOSI/SCK windows at the chip (PCB paths, chip

   inside chip1's. Expected: the sweep shows a window for each chip, chip0's
   edge close to today's launch point, and an overlap of the two.
   Refuted if chip0's window holds today's launch point with margin, or if a
   failing chip0 answers wrong at every phase.

**#6a spec written:** `docs/interfaces/spi1-mosi-eye-scan.md`.
- MOSI from one of four `clk`-domain sources (one `clk` early / today,
  each also on `clk` falling), then a register on `CLKOS` (the old
  `clk90`) with dynamic phase. A point is used only if the `CLKOS` edge
  is ≥ T/4 from any change of its source, so the crossing is safe by
  construction at every phase; together the points cover Δ from −3T/4 to
  +5T/4 around today's launch, both edges of the window.
  `mosi_sel` = 4 (reset) is today's MOSI, bit for bit.
- Delaying phase steps only (glitch-free per TN-02095).
- Known-answer checker per half: `READ(40..44)`, `READ(48..50)`,
  `WRITE(R, D)` → `{FF, D}`. Pattern uses `WRITE(6, 55/AA/00/FF)`:
  register 6 is the Zcheck DAC value, inert with the DAC powered off.
- Regbank 232–233 (control), 240–249 (read-only).
- Scan driven from the PC over the existing `REG_WRITE16`/`REG_READ16`
  (no new firmware); about 600 points per rate; power-cycle after.
- Chosen point: middle of the overlap, ≥ T/2 from any error (G5 rule),
  baked in as `mosi_sel`'s reset value and `CLKOS`'s static phase.
- Open: Kuntur `pll0` feedback mode and `PHASESEL` code; the `.sdc`
  form of the T/4 bound.

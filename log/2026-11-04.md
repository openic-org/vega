## T4 task #4: K7 `tun_aux` (Manuel's RTL, Claude's tb)

`kuntur` `e69999e`. Spec: `docs/interfaces/lvds-tunnel.md` §4.8.

**RTL:** new module `tun_aux` on `clk` / `rst_n_clk`, and an
`announce` output on `capture_buffer` (combinational,
`xfer_done && t == 1 && primed`, the edge `frame_rdy` toggles on).
- Shadow of RAM registers 0–21 from every `WRITE` at `rhd_start`;
  `dirty` on a changed value. `shadow` and `shadow_snap` are in a
  no-reset block (the walk writes all 22 before frame 0).
- At `announce`: `flags_snap`, `shadow_snap`, `send_config`
  (`dirty` or 1000 frames), `send_status` (300 frames, held pending
  behind `CONFIG`), `dirty` cleared.
- **`dirty` resets to 1.** After a lock drop the walk rewrites the
  same values, so without this, frame 0's `CONFIG` would carry
  `CONFIG_DIRTY = 0`, against §4.4.
- `flags_snap` now drives `frame_builder`'s flags byte. Not yet used:
  `send_config`, `send_status`, `cfg_addr`/`cfg_byte`, and the
  capture buffer's `alt_cmd`/`alt_answer`.

**Review findings, fixed by Manuel:** `cfg_byte` undriven; `shadow`
with two drivers; `shadow`/`shadow_snap` without a reset value inside
the async-reset block; `output reg` driven by `assign`; a missing
comma in the instance.

**tb (K8):** `flags` checked against a `CONFIG_DIRTY` reference built
from the `WRITE`s the RHD2164 models execute (not from the DUT). 9g:
`CONFIG_DIRTY` on exactly 3 frames: frame 0 at start-up, frame 0
after 8b's restart, and frame 11, during which T2 put
`WRITE(21, A5)` into sampling entry 0 (the walk wrote `FF`): a live
test of "changed while sampling". Mutation (`dirty` never set by a
write) fails 9b and 9g. 48 checks, 6 failures, all pre-existing
(T5/T7 FIFO pairs, `csb_reg` reset value).
